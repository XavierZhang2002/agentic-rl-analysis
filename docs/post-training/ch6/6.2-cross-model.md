# 6.2 跨模型对比与行业共识

!!! abstract "本节摘要"
    2025 年的横向对比只看三列：阶段数、RL 算法、有没有 Value 网络；2026 年这三列已经趋同，差异转移到**合并方式、一致性手段、异步策略**。本节保留 9 个系列与 7 个 2026 模型代的两套对比表，并据此修订六条行业共识、重排五个核心挑战，最后给出六条趋势判断。

!!! note "本节的位置"
    机制细节不再复述：[1.3](../ch1/1.3-pipeline-paradigms.md) 讲流程范式，[1.4](../ch1/1.4-reward-lineage.md) 讲奖励谱系，[4.3](../ch4/4.3-infra-consistency.md) 讲训推一致性。厂商细节见 ch5，本节只保留"横向可比的列"。

## 一、2025 与 2026 的两个对比维度

### 2025 口径：阶段、算法、Critic

| 模型 | 阶段数 | Pipeline 结构 | RL 算法 | Value 网络 |
|------|--------|-------------|---------|-----------|
| DeepSeek-R1 | 4 | Cold SFT → Reasoning RL → Rej.Sampling SFT → General RL | **GRPO** | 无 |
| DeepSeek-V3.2 | 3 | Specialist Distillation → Mixed RL → Speciale（推理变体） | **GRPO**（4 项稳定化） | 无 |
| Kimi K2 | ~3 | SFT → Agentic RL（RLVR + Self-Critique） | Policy Mirror Descent | 无 |
| Kimi K2.5 | ~3 | SFT → RL + Toggle + PARL | Policy Mirror Descent | 无 |
| Qwen3 | 4 | Cold SFT → Reasoning RL → Mode Fusion SFT → General RL | **GRPO** | 无 |
| MiniMax-01 | 5 | Short SFT → Long SFT → Short DPO → Long DPO → RL | GRPO（修改版） | 无 |
| MiniMax-M1 | 3 | CPT → SFT → RL | **CISPO** | 无 |
| GLM-5 | 5 | SFT → Reasoning RL → Agentic RL → General RL → Distillation | GRPO + IcePop | 无 |
| Seed/VAPO | 2-3 | (Cold SFT →) RL | **VAPO（PPO 改）** | **有** |

这张表在 2025 年能解释大部分差异：阶段数反映 pipeline 复杂度，算法决定稳定性，Value 网络决定信用分配精度。9 行覆盖 6 家、2–5 个阶段档位——最长的是 MiniMax-01 与 GLM-5，最简的是 Seed/VAPO。

但阶段数与能力没有单调关系：DeepSeek-R1 用 4 段把推理 RL 做成主线，Seed/VAPO 只用 2–3 段也在 AIME 上领先。决定效果的是每段"目标是否单一"，而不是段数本身。

### 2026 口径：合并、一致性、异步

所有人在算法上都收敛到 GRPO 变体，阶段数稳定在 3–5 段，Value 网络几乎消失。差异换到了另外三列：

| 模型 | 合并方式 | 一致性手段 | 异步策略 |
|---|---|---|---|
| **DeepSeek-V4 / V4.1** | 多教师全词表 OPD（>10 → >40 教师） | 未公开 | 异步 RL |
| **Kimi K3** | 9 专家（3 域 × 3 effort）+ **MOPD** | **全流程 QAT**（MXFP4/MXFP8） | partial rollout + 微虚机 |
| **GLM-5 / 5.3** | 跨阶段蒸馏 + 多教师 OPD | **TITO** + 确定性 top-k + 双侧 IS | 全异步（Slime） |
| **MiniMax M2.5** | 无（混合域训练） | 前缀树合并 + PD 分离 | Forge（Windowed FIFO） |
| **LongCat 2.0 / 2.5** | 多教师在线蒸馏 + MOPD | W4A4 数值一致 | DORA（load ratio 63%） |
| **Ling / Ring 2.6** | 无（迁移预训练 + LPO） | FP8 + LM head FP32 | ASystem（partial + 有界 stale） |
| **Qwen3.5 / 4-Max** | 跨模态 OPD（Omni） | TRACE（FP4 对齐） | QwenGyre（弹性 GPU） |

**读法**：算法列（GRPO/GSPO/SAPO）已经不能解释差异了——**合并方式决定能力上限，一致性手段决定能不能跑起来，异步策略决定成本**。这三列才是 2026 年的胜负手。

这也解释了 6.1 的披露收缩：算法可以一句话带过，而合并、一致性、异步恰恰是厂商最不愿公开的三类细节（[6.1](./6.1-overview-2026.md)）。

奖励设计对比不在本节展开，见 [1.4](../ch1/1.4-reward-lineage.md)；单模型内的算法演进图见 [6.3](./6.3-timeline-opinions.md)。

## 二、六条行业共识（2026 修订版）

六条共识来自 2025 年底对 9 个系列的归纳。2026 年的证据让其中三条改写，另外三条在更高强度上成立；每条标注状态与新判据。**改写不等于推翻**——原判断的方向大多仍对，变的是判据的粒度与优先级。

!!! success "共识一 · 轻量 SFT + 重度 RL：**成立**"
    Qwen3 用 3,995 条 query + 170 步 RL 拿到 +15 AIME；Seed 的 RFT 反而收窄探索空间；GLM-5.3 用同一基座把 Terminal-Bench 3.0 从 4.6 做到 28.3，说明后训练 scaling 远未见顶。
    机制见 [1.3](../ch1/1.3-pipeline-paradigms.md)。

!!! success "共识二 · Hard Clipping 是原罪：**改写**为「约束什么量、在哪一层」"
    DPPO 直接估计散度、TRM 用序列级 mask、LPO 把组采样看成 simplex 上的 listwise 投影；硬裁剪只是"token 级 + 约束 ratio"这一格的原始形态。
    裁剪 → 门控的演进并未被推翻，但它只占 2026 二维矩阵的一角，见 [2.7](../ch2/2.7-trust-region-2026.md)。

!!! success "共识三 · MoE 需要专用 RL：**改写**为「一致性优先于目标函数」"
    R3 的路由回放把 Qwen3-30B-A3B 上的成绩从 62.23 提到 71.83，优于 GSPO/TIS；GLM-5 的 DSA top-k（k=2048）无法回放，只能确定性算子 + 冻结 indexer；Kimi K3 用全流程 QAT 从根上消除训推差。
    序列级 ratio 是补丁，不是根治——工程细节见 [4.3](../ch4/4.3-infra-consistency.md)。

!!! success "共识四 · Query 质量优先：**改写**为「rollout 分配是一等问题」"
    Pilot-Commit 先 pilot 再分配，比 DAPO 省 4.0× rollout；ReMix 复用旧轨迹，缩减 30–450×；PCL 用价值模型预测可学 prompt，比实际 rollout 快 12–17×。
    Query 选择降级为分配的一个子问题，见 [3.1](../ch3/3.1-rollout-allocation.md)。

!!! success "共识五 · 大模型 RL + 小模型蒸馏：**成立**"
    两层分工没有变：DeepSeek V4.1 用 >40 个教师做全词表 OPD，Kimi K3 用 9 专家 + MOPD，Qwen3 从 235B 蒸到 4B 仍只要约 1/10 GPU 成本。
    变的是"蒸馏"升级为"在策略蒸馏合并"，见 [3.3](../ch3/3.3-merging-opd-mopd.md)。

!!! success "共识六 · 工程实现不亚于算法：**成立**，且权重上升"
    GLM-5 的非确定性 top-k 让训练数步内崩溃；0.1% 的 re-tokenization 不匹配不报错、只静默拉低收敛质量；MiniMax M1 需把 Adam β₂ 从 0.999 改到 0.95、输出头改 FP32。
    2026 年这类"静默失败"被归并到一致性（[4.3](../ch4/4.3-infra-consistency.md)）与验证器（[4.4](../ch4/4.4-verifier-failures.md)）两条线。

## 三、五个核心挑战

五个挑战沿用 2025 年的划分，但权重变了：**Critic 降级、验证器升级**；信任域仍是算法主线，长序列与遗忘仍是系统问题。

### 挑战一：信任域设计——从"clip 形状"到"约束什么量"

2025 年的主线是把 ratio 裁得更平滑（PPO → DAPO → CISPO → GSPO → SAPO）。2026 年四条路线分别改约束对象与层级：

| | **token 级** | **序列级** | **listwise** |
|---|---|---|---|
| **约束 ratio** | PPO / GRPO / DAPO / CISPO | GSPO | — |
| **约束散度** | — | TRM | LPO |
| **不显式约束（压方差）** | SAPO / OTB | — | — |

2025 年的工作主要在第一行做文章：GSPO 挪到序列列，SAPO 把硬边界换成连续门控；2026 年把行也撑开了，右下角（listwise + 散度）仍是空的。未解的是散度估计本身的方差，以及 listwise 在异步、部分 rollout 下的可比性，详见 [2.7](../ch2/2.7-trust-region-2026.md)。

### 挑战二：Critic 规模化困境——已降级

VAPO 在 AIME 2024 上 60.4 vs DAPO 50.0，证明修好 Critic 的 Value-Based 仍最准；但为 671B MoE 配同规模 Critic 要多 25–50% 显存，且依赖 Value Pretraining（去掉后 60→11）。2026 年出现两条免 Critic 的稠密信号：

| 路线 | 额外模型 | 信号粒度 | 主要风险 |
|---|---|---|---|
| Critic（VAPO） | 与 actor 同规模 | token 级 GAE | 显存 +25–50%，冷启动难 |
| 概率比（Progress Advantage） | 仅参考策略 | step 级 | 对 $\pi_{\text{ref}}$ 敏感 |
| 自蒸馏（SDPO） | 无（同模型双条件） | token 级 | 特权信息必须可靠 |

三条路线不互斥：小模型上 Critic 仍最准，大 MoE 上概率比/自蒸馏更现实。结论从"Critic 不可替代"改为"**Critic 是最准的一条，不是唯一一条**"，见 [3.2](../ch3/3.2-dense-signal.md)。

### 挑战三：验证器可靠性——原「不可验证奖励」升级

不可验证任务（写作、开放问答、安全）仍依赖神经 RM，Reward Hacking 没有被根本解决。2026 年更麻烦的发现是**可验证奖励也不等于可靠奖励**：CIR/SR 显示"答对"不代表推理链是必要的（2604.22074）；外延验证会让模型学会利用验证器盲区（2604.15149）；多维 rubric 的子维度之间存在系统性背离（2610.26685）。

工业应对是把验证器当模型来训：GLM-5.3 的 verifier 三检（已知正确解必须给奖、空操作必须不给、未完成必须不给），再用 solver 轨迹封堵捷径解；奖励搭配收敛为"规则打底 + GRM 鲁棒 + rubric 可审计"。四类测试与失败模式见 [4.4](../ch4/4.4-verifier-failures.md)。

开放问题仍在：能否用 solver 的作弊轨迹反向训练验证器？目前这一步还是人工封堵。

### 挑战四：长序列的优化粒度

Token 级（PPO/GRPO/DAPO/CISPO/VAPO）有最细的信用分配，但 IS ratio 方差随序列长度放大；序列级（GSPO）稳定、MoE 友好，却抹平序列内差异；SAPO 在 token 级定义 soft gate、理论上自动逼近序列级行为，把"token vs sequence"变成连续谱。

2026 年的 TRM 从另一侧给出证据：token 级约束对序列散度的界是 $O(T^2)$，长 CoT / 长 trajectory 必须上移到序列级（[2.5](../ch2/2.5-cispo-gspo.md)）。未解的是极端长度下的 listwise 前提与异步 staleness（[2.6](../ch2/2.6-sapo.md)）。

### 挑战五：多阶段 pipeline 的能力遗忘

2–5 阶段 pipeline 的核心矛盾没变：后一阶段的目标会降级前一阶段的能力。2025 年的三种解法仍然有效——GLM-5 跨阶段蒸馏（group size=1，教师分数差作 advantage）、DeepSeek-R1 从 Base 重训、MiniMax-01 的短-长分离。

2026 年把"遗忘"升级成结构问题：与其串行修补，不如**先训专家再合并**（OPD/MOPD）。代价是教师调度、显存与带宽，且合并后通常不再继续 RL，见 [3.3](../ch3/3.3-merging-opd-mopd.md)。

五个挑战的关系可以压成一句：**信任域决定梯度怎么流，一致性决定 ratio 是否有意义，验证器决定奖励是否指向想要的行为，粒度与遗忘决定信号在序列和阶段之间如何传递**——不存在单点解法。

## 四、趋势判断

原趋势表有 8 行，其中两组是同一趋势的延伸，已合并；其余 4 行按 2026-11 的证据更新判断。

| 趋势 | 2026 的证据 | 判断 |
|------|------|------|
| **Agentic RL 成为主战场 → 环境飞轮** | V4、K3、M3、GLM-5.3、LongCat-2.5 全部以 agent 为核心卖点；EnvFactory、SPADE、AutoEnvScaling 报出 25× 有效环境率 | 已兑现；竞争点从"环境质量"转到"环境产能" |
| **后训练投资继续增长 → 预算分配成为一等问题** | GLM-5.3 用同基座把 Terminal-Bench 3.0 从 4.6 做到 28.3；Pilot-Commit 省 1.9–4.0× rollout、ReMix 30–450× | 已兑现，后训练 scaling 远未见顶；收益从"投多少"转向"每一步花在哪" |
| **模型辅助自身训练** | M2.7 吸收 30–50% 日常迭代；GLM-5.3 用 research agent 造环境 | 部分兑现；仍是"人设计、模型执行" |
| **多模态 RL 合并进主流程** | K2.5 的 zero-vision SFT、Qwen3.5-Omni 的跨模态 OPD | 已兑现；OPD 成为跨模态迁移工具 |
| **MoE RL 算法成熟化** | 算法趋同（GRPO 变体），差异转向**一致性**（R3/QAT/确定性算子） | **改写**：不是"算法成熟"，是"算法不再是瓶颈" |
| **架构-训练协同设计** | Qwen3.5 的 GDN+MoE、GLM-5.2 的 IndexShare、MiniMax 的 MSA | 已兑现；架构创新越来越依赖"训练侧能不能配合" |

合并说明：原表"（新增）环境飞轮"并入 Agentic RL 行，"（新增）预算分配成为一等问题"并入后训练投资行——它们本来就是同一趋势的延伸，不是独立趋势。

两条被合并的趋势恰好也是 2026 年最容易被低估的：环境从"数据的一部分"变成"可规模化生产的资产"，预算从"训练超参"变成"与算法同级的决策变量"。

如果只记一条：2026 年的胜负手不在损失函数，而在**合并方式决定能力上限、一致性决定能不能跑起来、预算分配决定成本**。
