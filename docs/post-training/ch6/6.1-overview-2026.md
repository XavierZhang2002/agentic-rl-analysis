# 6.1 2026 技术报告全景

!!! abstract "本节摘要"

## 二、披露强度分级

| 级别 | 定义 | 2026 年的代表 |
|---|---|---|
| **A** | 给出阶段划分 + 算法 + 奖励 + 工程细节 | GLM-5、Kimi K3、DeepSeek V4、MiniMax M2 系列、Ling 2.6 |
| **B** | 给出阶段划分或某一层细节，缺算法/奖励 | GLM-5.2 / 5.3、LongCat 2.0 / 2.5、Qwen3.5-Omni、DeepSeek V4.1-Flash |
| **C** | 只有 benchmark 与架构 | Qwen3.5 基座、Qwen4-Max、Kimi K2.6 / K2.7、MiniMax M3 |
| **D** | 无技术披露 | 闭源五家（OpenAI 例外，见附录） |

**三个结论**：

1. **披露在收缩**：2025 年 GLM-5 / Kimi K2 / Qwen3 都有完整技术报告；2026 年 GLM-5.2、Qwen3.5 基座、Qwen4-Max、Kimi K2.6/K2.7 都只有博客。
2. **但机制在收敛**：披露越少，方法越像——所有人都在做 OPD/MOPD、异步、环境合成。
3. **"没报告"不等于"没进展"**：Qwen3.5-Max、GLM-5.2 这类只有博客的版本，往往把关键改动写进了**下一篇论文**（SAO、IndexCache）而不是模型卡。

## 四、怎么读"没披露"的报告

遇到 C 级（只有 benchmark）的报告，不要用别家方法推测。可行的做法只有三条：

1. 找**同期的论文**（例如 MiniMax M3 → MSA 论文；GLM-5.2 → IndexCache 论文）；
2. 找**框架/产品文档**（例如 Gemini 的 RLFT 托管服务说明、HuggingFace 模型卡的训练配置）；
3. 标注"未披露"，等下一版。
