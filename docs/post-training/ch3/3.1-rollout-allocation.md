# 3.1 预算分配：rollout allocation

!!! abstract "本节摘要"
    GRPO 家族默认"每个 prompt 固定采 $G$ 条"，2026 年这条假设被打破：预算在 prompt 之间怎么分，成了一个独立的设计维度。Pilot-Commit 用 pilot 方差做事前分配（比 GRPO 省 **1.9×** rollout、比 DAPO 省 **4.0×**），ReMix 复用历史轨迹（**30–450×**），PCL 用价值模型预测难度（快 **12–17×**），SAO 直接把组采样换成单 rollout（GLM-5.2 已部署）。本节给四条路线的机制、该不该做的判断，以及它们与 staleness 补丁（SAT/COPC）的关系。

!!! note "与 1.3、2.7 的分工"
    这里只谈"多少 rollout 花在哪些 prompt 上"；范式选型（单阶段/多阶段、SFT 与 RL 的编排）见 [1.3 流程范式](../ch1/1.3-pipeline-paradigms.md)，目标函数与信任域见 [2.7 信任域](../ch2/2.7-trust-region-2026.md)。

---

## 一、为什么分配成了一等问题

GRPO 家族的默认做法是每个 prompt 采 $G$ 条、$G$ 固定。DAPO 的 Dynamic Sampling（[2.3 DAPO](../ch2/2.3-dapo.md)）已经指出**全对/全错**的 prompt 产生零梯度，应事后过滤。2026 年的工作把"事后过滤"推进成"事前分配"：

> 问题不是"要不要多采样"，而是"**这一步的 rollout 预算该怎么在 prompt 之间分配**"。

成本结构是直接动机：agentic 任务的 rollout（环境交互、长轨迹、工具调用）常比一次参数更新更贵，而 prompt 的信息量差异极大——固定 $G$ 让简单题与难题付同样的钱。

## 二、四条代表性做法

| 方法 | 分配依据 | 报告的收益 | 主要代价 |
|---|---|---|---|
| **Pilot-Commit** | 小预算 pilot 估每个 prompt 的 reward 方差 | 达目标精度省 **1.9×**（vs GRPO）、**4.0×**（vs DAPO） | pilot 本身要花预算 |
| **ReMix** | 复用旧策略轨迹，mix-policy 目标 + 高 UTD | rollout 缩减 **30–450×** | off-policy 偏差需显式校正 |
| **PCL** | 价值模型预测"约 50% 难度"的 prompt | 预测快 **12–17×** | 预测器会随策略漂移 |
| **SAO** | 单 rollout + 价值模型 + 严格双侧 token 级裁剪 | 采样量降到 1/G | 价值模型补组内信息 |

**Pilot-Commit**（[arXiv:2605.26606](https://arxiv.org/abs/2605.26606)）两阶段：先用一小部分预算做 pilot，估计每个 prompt 的 reward 方差；再把 prompt 分成"高方差（有信息量）"与"低方差（无梯度）"，高方差者拿走剩余预算，低方差者跳过。本质是把 Dynamic Sampling 从**事后过滤**改成**事前分配**。

**ReMix**（[arXiv:2507.06892](https://arxiv.org/abs/2507.06892)，ICLR 2026）不丢弃历史 rollout，用 mix-policy 目标把旧策略产生的轨迹也算进来，配合高 UTD（update-to-data ratio）。省的是重采样，花的是 off-policy 校正。

**PCL**（[arXiv:2510.01135](https://arxiv.org/abs/2510.01135)，ICLR 2026）用一个价值模型**预测**哪些 prompt 处于约 50% 难度（最可学区间），预测速度比实际跑 rollout 快 **12–17×**。与 Pilot-Commit 的分工：一个在线估方差，一个离线预测难度。

**SAO**（[arXiv:2607.07508](https://arxiv.org/abs/2607.07508)，已在 GLM-5.2 部署）把组采样换成**单 rollout 采样**，配价值模型与严格双侧 token 级裁剪，在异步设定下稳定训练 1000 步。单 rollout 把采样成本降到 $1/G$，但需要价值模型补回组内比较丢失的信息——典型的"省 rollout 换模型"交易。GLM-5.2（约 750B-A40B）的 agentic RL pipeline 已用；TITO、双侧 IS 与 staleness 边界的实现细节见 [4.3 基础设施与一致性](../ch4/4.3-infra-consistency.md)。
## 三、异步下的 staleness

分配改变"样本何时、以多旧的状态产生"，因此与异步强耦合。2026 年的两个补丁：

- **SAT**（[arXiv:2607.18722](https://arxiv.org/abs/2607.18722)）：clip 端点随 staleness 自适应收缩——越旧的样本允许的偏移越小。
- **COPC**（[arXiv:2610.09597](https://arxiv.org/abs/2610.09597)）：policy 与 advantage 双通道耦合校正，报出 64 步 staleness 仍稳定。

两者是分配器的**安全边界**：分配越激进（单 rollout、高 UTD），越依赖它们压住 stale 样本的梯度。系统侧实现见 [4.3](../ch4/4.3-infra-consistency.md)。
