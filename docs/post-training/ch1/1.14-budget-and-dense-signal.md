# 1.14 预算分配与免 Critic 的稠密信号（2026）

!!! abstract "本节摘要"
    2026 年有两条线绕开了"设计更好的损失函数"：一条是**把 rollout 预算花在对的 prompt 上**（Pilot-Commit、ReMix、PCL、SAO），另一条是**不训练 Critic 也能拿到 token/step 级信号**（Progress Advantage、SDPO 族）。前者让"同样算力下的收益"主要来自分配效率，后者让 VAPO 式的 critic 路线不再是唯一解。

!!! note "与 1.7 的关系"
    1.7 的结论是"VAPO 证明了 Value-Based 更强，只是大 MoE 上 Critic 太贵"。本节要补充的是：**2026 出现了两条成本远低于 Critic 的替代路径**，这个结论需要从"Critic 不可替代"改成"Critic 是一条路线，不是唯一路线"。

---

## 一、rollout 分配：从"多采样"到"把预算花在对的 prompt 上"

### 1.1 为什么这成了一个独立问题

GRPO 家族的默认做法是：每个 prompt 采 $G$ 条，$G$ 固定。DAPO 的 Dynamic Sampling 已经指出**全对/全错**的 prompt 产生零梯度，应该过滤（1.6 节，单项 +8 AIME）。2026 年的工作把这个直觉推进了一步：

> 问题不是"要不要多采样"，而是"**这一步的 rollout 预算该怎么在 prompt 之间分配**"。

### 1.2 四条代表性做法

**Pilot-Commit**（[arXiv:2605.26606](https://arxiv.org/abs/2605.26606)）

两阶段：先用一小部分预算做 **pilot**，估计每个 prompt 的 reward 方差；再把这批 prompt 分成"高方差（有信息量）"与"低方差（无梯度）"，**高方差者拿走剩余预算，低方差者直接跳过**。

- 效果：达到目标精度比 GRPO 省 **1.9×** rollout，比 DAPO 省 **4.0×**。
- 本质：把 Dynamic Sampling 的"事后过滤"改成了**事前分配**。

**ReMix**（[arXiv:2507.06892](https://arxiv.org/abs/2507.06892)，ICLR 2026）

不丢弃历史 rollout，而是用 mix-policy 的目标把**旧策略产生的轨迹**也算进来（配合高 UTD，update-to-data ratio）。

- 效果：rollout 缩减 **30–450×**（取决于任务）。
- 代价：off-policy 偏差需要显式校正，对异步系统要求更高。

**PCL**（[arXiv:2510.01135](https://arxiv.org/abs/2510.01135)，ICLR 2026）

用一个价值模型**预测**哪些 prompt 处于"约 50% 难度"（即最可学区间），预测速度比实际跑 rollout 快 **12–17×**。

- 与 Pilot-Commit 的区别：一个用在线方差估计，一个用离线价值模型预测。

**SAO**（[arXiv:2607.07508](https://arxiv.org/abs/2607.07508)，已在 GLM-5.2 部署）

把组采样换成**单 rollout 采样**（每个 prompt 只采一条），配一个价值模型与**严格双侧 token 级裁剪**，在异步设定下稳定训练 1000 步。

- 意义：单 rollout 意味着**采样成本减半到 1/G**，但需要价值模型补回组内比较损失的信息——这是"省 rollout 换模型"的典型交易。
- 工业验证：GLM-5.2（约 750B-A40B）的 agentic RL pipeline 已用。

### 1.3 异步下的额外问题：staleness

异步 RL 里，rollout 用的策略版本与训练时的版本可能差好几步。2026 年的两个补丁：

- **SAT**（[arXiv:2607.18722](https://arxiv.org/abs/2607.18722)）：让 clip 端点随 staleness 自适应收缩——越旧的样本，允许的偏移越小。
- **COPC**（[arXiv:2610.09597](https://arxiv.org/abs/2610.09597)）：policy 与 advantage 双通道耦合校正，报出 64 步 staleness 仍稳定。

!!! tip "给工程团队的一句话"
    如果你的 RL 训练里 rollout 成本 > 训练成本（agentic 场景常见），**先做 rollout 分配，再谈算法**。Pilot-Commit 与 PCL 都是"加一个预测器"级别的改动，不需要重写训练循环。

## 二、免 Critic 的稠密信号：两条便宜的路

### 2.1 为什么 Critic 贵

VAPO（1.7）用 Critic 拿到 token 级 GAE，代价是：

- 参数量 +25–50%（与 actor 同规模）；
- 需要 Value Pretraining、Decoupled GAE、Length-Adaptive GAE 三件套才训得动；
- 671B 级 MoE 上工程不可行。

于是 2026 年出现了两条**不训练 Critic**的路径。

### 2.2 路径一：用策略自身的概率变化当信号（Progress Advantage）

**论文**：*Neglected Free Lunch from Post-training: Progress Advantage for LLM Agents*（[arXiv:2606.26080](https://arxiv.org/abs/2606.26080)，NeurIPS 2026）

核心结论：在"策略 $\pi_\theta$ 与参考策略 $\pi_{\text{ref}}$"之间，**token 级的 log-prob 比率本身就能恢复最优 advantage**：

$$
\hat{A}^{\text{prog}}_t \;\propto\; \log \frac{\pi_\theta(y_t \mid s_t)}{\pi_{\text{ref}}(y_t \mid s_t)}
$$

也就是说，不需要 PRM、不需要 Critic——**只要有一个参考策略**，就能免费得到 step 级打分。参考策略可以是 SFT 模型、上一轮 checkpoint，或同批次的其他 rollout。

- 代价：需要选一个合适的 $\pi_{\text{ref}}$，且它的质量决定信号质量。
- 适用：agent 多步任务（每步都有 token 分布偏移，天然有信号）。

### 2.3 路径二：用特权信息做自蒸馏（SDPO 族）

**SDPO**（[arXiv:2601.20802](https://arxiv.org/abs/2601.20802)，ICML 2026）把"反馈/答案/工具返回"等**特权上下文**作为教师信号，让模型在"看到答案"与"没看到答案"两种条件下做自蒸馏：

$$
\mathcal{L}_{\text{SDPO}} = \mathrm{KL}\!\left(\pi_\theta(\cdot \mid x, c_{\text{priv}}) \,\Big\|\, \pi_\theta(\cdot \mid x)\right)
$$

学生与教师是同一个模型，只差特权信息——因此不需要额外的奖励模型或 Critic，却能得到 token 级的稠密梯度。

- **SDAR**（[arXiv:2605.15155](https://arxiv.org/abs/2605.15155)）把它作为门控辅助目标，RL 为主干。
- 影响力：SDPO 是本年度引用最高的 RL 论文之一（466 引，ICML 2026）。

### 2.4 三条路线的成本对比

| 路线 | 额外模型 | 信号粒度 | 主要风险 |
|---|---|---|---|
| Critic（VAPO） | 与 actor 同规模 | token 级 GAE | 显存 +25–50%，冷启动难 |
| 概率比（Progress Advantage） | 仅参考策略 | step 级 | 参考策略选择敏感 |
| 自蒸馏（SDPO） | 无（同模型双条件） | token 级 | 特权信息必须可靠 |

!!! success "结论"
    "Critic 规模化困境"的解法不是"把 Critic 做小"，而是**换一种免费的信号源**。这三条路线不是互斥的：小模型上 Critic 仍最准，大 MoE 上概率比/自蒸馏更现实。

## 三、把两条线合起来看：2026 的"收益来源"迁移

| 2025 的收益来源 | 2026 的对应变化 |
|---|---|
| 更好的 clip 形状（+2~4 分） | 转向"约束什么量、在哪一层"（1.13） |
| 更多采样（G 增大） | 转向"预算怎么分配"（本节一） |
| 更大 Critic / 更好 GAE | 转向"免 Critic 的免费信号"（本节二） |
| 更多数据 | 转向"环境与验证器质量"（ch2 主题） |

## 开放问题

1. **Pilot 的统计效率**：pilot 阶段本身要花预算，当 prompt 分布漂移快时，"先探测再分配"是否仍划算？
2. **单 rollout 的方差**：SAO 用价值模型补信息，但价值模型在大 MoE 上同样昂贵——它是不是把 Critic 换了个名字？
3. **参考策略的选择**：Progress Advantage 对 $\pi_{\text{ref}}$ 敏感，是否存在"自适应参考"的稳定做法？
