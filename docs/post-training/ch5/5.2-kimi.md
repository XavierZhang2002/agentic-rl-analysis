# 5.2 Kimi

!!! abstract "本节摘要"
    Kimi 三代走完了"推理 Scaling → Agentic 训练 → 多模态 Agent"的路径：K1.5 把 RL 上下文扩到 128K 并系统化了 long2short，K2 用 MuonClip 稳住 MoE 训练、并以 3K+ 真实 MCP 工具做 Agentic 数据合成，K2.5 以 PARL 做并行 Agent 协作。2026 年的 K3 把后训练拆成 **9 个 RL 专家**、再以 **MOPD** 合并，并把一致性交给量化与 AgentENV。

---

## 一、发布矩阵

| 模型 | 日期 | 规模 | 后训练要点 |
|---|---|---|---|
| **K1.5** | 2025-01 | 未公开 | online policy mirror descent（无 value 网络）；128K RL 上下文；CoT RM 98.5%；long2short；AIME 77.5 / MATH-500 96.2 |
| **K2** | 2025-07 | 1.04T / 32.6B | MuonClip（τ=100，零 loss spike）；3K 真实 + 20K 合成 MCP；Self-Critique Rubric；开源 |
| **K2.5** | 2026-02 | 1.04T / 32B + MoonViT-3D | Zero-Vision SFT、早期融合 10:90、PARL、Toggle；262K 上下文 |
| K2.6 | 2026-04-20 | 未公开 | **无 RL 披露**；Agent Swarm 扩到 300 子 agent / 4,000 步 |
| K2.7 Code | 2026-06-12 | 1T / 32B | **无后训练披露**；thinking token 约 −30% |
| **K3** | 2026-07-16（权重 07-27） | 2.78T / 104.2B，93 层，1M ctx | SFT → **9 个 RL 专家**（3 域 × 3 effort）→ **MOPD**；QAT(MXFP4/MXFP8) 贯穿 SFT+RL；1M agentic RL（AgentENV 微虚机） |

K3 的关键不在算法而在**一致性**：rollout 与训练共用同一量化，从根上消除训推差异；AgentENV 的 checkpoint/resume 为 133/49 ms，累计 5,121 万 sandbox（见 [4.3](../ch4/4.3-infra-consistency.md)）。MOPD 机制见 [3.3](../ch3/3.3-merging-opd-mopd.md)。

## 二、后训练 Pipeline

### 2.1 K1.5：长上下文 RL

- **算法**：online policy mirror descent + KL 正则，明确不用 value 网络（认为 credit assignment 会损害长 CoT 探索）；二元结果奖励 r ∈ {0,1}；每轮迭代重置优化器。
- **上下文**：4K → 32K → 128K 渐进扩展；**Partial Rollout** 固定每轮 token 预算、未完成轨迹进 replay buffer 下一轮续跑，避免长轨迹计算浪费。
- **采样**：课程采样（易→难）稳定早期训练 + 优先采样（概率 ∝ 1 − success_rate）聚焦尚未掌握的难题。
- **long2short**：模型合并 / 最短 Rejection Sampling / DPO 三种方法均"中等"，**Long2Short RL（长度惩罚 + 缩短 max rollout）最优**——AIME 2024 **60.8**，平均仅 **3,272** tokens。
- **CoT RM**：奖励模型先写推理再打分，准确率 **98.5%**，传统 RM 仅 84.4%。

### 2.2 K2：Agentic 训练

- **三阶段数据合成**：3K+ 真实 MCP 构建工具与领域规格 → 生成 Agent 定义与带 Rubric 的任务 → 工具模拟器 + Judge 产出并过滤轨迹。模拟器充当世界模型（成功 / 部分失败 / 边缘情况），无需真实 API 调用。
- **架构**：1.04T/32.6B、384 专家；注意力头 128 → 64，128K 上下文省 **83%** 推理 FLOPs，训练 loss 仅损 0.5–1.2%。
- **奖励**：不训独立 RM，模型按"核心 / 规范（反 reward hacking）/ 人工标注"三类 rubric 自评；闭环 critic 用 RLVR 的客观信号校准主观判断。
- **结果**：SWE-bench Verified **65.8**、LiveCodeBench v6 **53.7**、AIME 2025 49.5、MATH-500 97.4、FACTS 88.5（非 thinking 模式）；LMSYS 开源第一、总第五（3000+ 票）。

### 2.3 K2.5：多模态与并行 Agent

- **架构**：K2 骨干 + MoonViT-3D，262,144 tokens；**早期融合 + 10:90 视觉:文本** 在所有指标（含纯文本）上优于晚期融合 + 50:50。
- **Zero-Vision SFT**：SFT 完全不用视觉数据（图像操作走编程式 IPython），且加入人工视觉轨迹反而损害泛化。
- **视觉 RL 反哺文本**：MMLU-Pro 84.7 → **86.4**、GPQA-Diamond 84.3 → **86.4**、LongBench v2 56.7 → **58.9**。
- **PARL**：冻结子 Agent、只训编排器；r = λ₁·r_parallel + λ₂·r_finish + r_perf，λ 退火至零（防串行坍缩与虚假并行）。**Toggle** 交替预算受限 / 标准阶段，省 **25–30%** 输出 token。

## 三、关键工程点

1. **MuonClip**：Muon 的满秩更新会让 MoE 注意力 Q/K 奇异向量对齐、logits 爆炸；QK-Clip 按 γ_h = min(1, τ/S_max^h) 逐头缩放（τ=100），15.5T token 训练**零 loss spike**，约 70K 步后谱范数降到阈值以下、自动停用。
2. **训练-推理混合部署**：Megatron + vLLM 作为同一 GPU 上的 Kubernetes sidecar，训练→推理 <1 分钟、推理→训练 ~10 秒；crun 沙箱 0.04 s 启动（Docker 0.12 s）、120 容器/秒。
3. **长尾调度三板斧**：Partial Rollout 暂停/恢复长尾轨迹、Enforcer 约束解码保证工具调用合法、TypeScript 声明工具；K2 全 1T 参数更新 <30 秒（分布式 checkpoint 引擎已开源）。

## 四、失败经验

- **长上下文 RL 会被长尾拖垮**：128K 窗口下等一条轨迹跑完就是浪费，Partial Rollout 是被逼出来的设计。
- **Muon 直接上 MoE 会炸**：不稳定被专家切换放大，必须配"后更新裁剪"的 QK-Clip，而不是改优化器本身。
- **SFT 塞视觉轨迹反而更差**（K2.5）：联合预训练已建立视觉-文本对齐，显式视觉监督是负向。
- **K2.6 / K2.7 均未披露 RL**：不能把 K2 的数据合成结论外推到这两代。

## 五、2026 变化

- 后训练从"一个 RL 阶段"变成"**专家分治 + 合并**"：K3 的 9 个专家按域 × effort 切分，再用 MOPD 收拢（[3.3](../ch3/3.3-merging-opd-mopd.md)）。
- 一致性优先于算法：QAT 量化贯穿 SFT+RL，1M agentic RL 跑在 AgentENV 微虚机上（[4.2](../ch4/4.2-environment.md)、[4.3](../ch4/4.3-infra-consistency.md)）。
- Agent Swarm 规模继续涨（K2.6 300 子 agent / 4,000 步），但披露只剩规模、没有算法。
