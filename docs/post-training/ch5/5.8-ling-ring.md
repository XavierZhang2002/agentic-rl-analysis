# 5.8 Ling / Ring（蚂蚁）

!!! abstract "本节摘要"
    蚂蚁的 Ling/Ring 系列在 2026 年做了两件别人没做的事：① 把信任域从"固定比值掩码"改成**概率感知的二元 KL 双侧掩码（KPop）**；② 用 **partial rollout + 有界 staleness** 做到"吞吐接近异步、稳定性等同同步"。前者是算法增量，后者是基础设施增量。

---

## 一、发布矩阵

| 模型 | 日期 | 规模 | 上下文 | 关键动作 |
|---|---|---|---|---|
| **Ling-2.5 / Ring-2.5** | 2026-02-13 | 1T / 63B | 1M | 混合线性注意力架构迁移（1:7 MLA:Lightning）；正确性 + 冗余复合奖励 |
| **Ling-2.6 / Ring-2.6** | 2026-06-13 | 104B ~ 1T | 256K | 架构迁移预训练 + Evo-CoT / LPO / 双向偏好对齐 + **KPop** + ASystem |

> 注意：2.0 / Ring-2.0 属 2025 代，本节不展开。

## 二、KPop：把 IcePop 的常数比换成二元 KL

### 2.1 问题

IcePop 用**均匀常数比**做掩码——隐含假设是"每个 token 的训练/推理失配程度相同"。实际不是：**低概率 token 的失配被过度惩罚**，因为这些 token 的比值本身方差就大。

### 2.2 做法

KPop 把掩码换成**全词表上的二元 KL 事件划分**：

$$
m(y_t) = \mathbb{1}\left[\mathrm{KL}\big(\pi_{\text{rollout}}(\cdot \mid y_{<t}) \,\|\, \pi_\theta(\cdot \mid y_{<t})\big) \le \phi\right]
$$

关键是它**在整词表的分布上算 KL**，而不是只看采样到的那个 token 的比值。整个方法只引入**一个超参 $\phi$**；约束量的选型见 [2.7 信任域与目标函数](../ch2/2.7-trust-region-2026.md)。

### 2.3 效果（官方消融）

| 指标 | 改动前 | 改动后 |
|---|---|---|
| SWE-bench Verified | 70.8% | **76.28%** |
| reward | 0.54 | **0.68** |

!!! warning "口径提醒"
    Ring-2.6 发布模型的 SWE-bench 是 **74.00**（high 配置），KPop 的 76.28 是另一组"轻量 agent"消融的起点/终点——**两者不能直接相减**。

## 三、ASystem：部分 rollout + 有界 stale

- **Partial rollout**：用全局 **token 预算 $\Phi$** 门控，一条长轨迹可以切片生成；
- **有界 staleness**：`max_staleness × consumer_batch_size` 作为上界，超界丢弃；
- 目标：**吞吐接近异步、稳定性等同同步**；
- 细节：FP8 下 LM Head 双侧用 FP32，换约 **+2 分** reward（一致性机制见 [4.3 训推一致性](../ch4/4.3-infra-consistency.md)）。

## 四、其余后训练要点

- **架构迁移预训练**：2.6 不是从零训，而是在已有架构上做迁移——这是"换架构不重训"的工程选择。
- **Evo-CoT**：让 CoT 结构随训练演化，而不是固定模板。
- **LPO**：把 group-based PG 看成 response simplex 上的投影（见 [2.7 信任域](../ch2/2.7-trust-region-2026.md)）。
- **双向偏好对齐**：偏好数据做正反两向，降低单向偏差。

## 五、怎么读 Ling/Ring 的报告

- **值得读**：KPop 的推导（为什么常数比会过度掩码低概率 token）——这是 2026 年信任域讨论里最"具体"的一个改进。
- **别期待**：大规模工程细节（相比 GLM/Kimi，披露较克制）。
- **注意**：2.5 的算法细节主要来自媒体报道，技术报告是 2.6 才有的。
