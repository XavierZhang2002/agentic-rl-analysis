# 5.3 Qwen

!!! abstract "本节摘要"
    Qwen 的路线是"每代加一个阶段"：Qwen2.5 用六维 RM + 方差优先采样搭出 SFT → DPO → GRPO → 长上下文四段式，Qwen3 用 **3,995 条 query / 170 步**换来 AIME +15 并做出 Thinking Mode Fusion，Qwen3.5 转向 GDN+MoE 混合架构。GSPO 与 SAPO 则在算法层面修掉了 GRPO 在 MoE 上的 token 级缺陷。

---

## 一、发布矩阵

| 模型 / 论文 | 日期 | 规模 | 后训练要点 |
|---|---|---|---|
| **Qwen2.5** | 2024-12 | 0.5B–72B | SFT ~1M → DPO ~150K → GRPO（方差优先）→ 128K 长上下文；六维 RM |
| **Qwen3** | 2025-05 | 0.6B–235B | Cold SFT 长 CoT → Reasoning RL（3,995 query / 170 步）→ Mode Fusion → General RL（20+ 类别）；AIME 2024 81.5 |
| **GSPO** | 2025-07 | 算法论文 | 序列级 importance ratio，去掉 Routing Replay；同条件 AIME +2–4 |
| **SAPO** | 2025-11 | 算法论文 | sigmoid 平滑门控替代硬裁剪；Qwen3-VL 生产验证 |
| **Qwen3.5**（8 档开源） | 2026-02-15 | 397B-A17B 旗舰 | 官方承认**无新 RL 算法**，靠"把 RL 任务 / 环境规模化"；基座技术报告至今未公开 |

## 二、后训练 Pipeline

### 2.1 Qwen2.5：四段式与六维 RM

- 四段：SFT（~1M）→ DPO（~150K 偏好对）→ GRPO（方差优先查询选择）→ 长上下文微调（128K）。
- **六维 RM**：Truthfulness / Helpfulness / Conciseness / Relevance / Harmlessness / Debiasing 独立评分；分维度打分让 DPO 能只在单个维度上构造偏好对，避免维度间干扰。
- **方差优先采样**：先对每个 query 预采样算奖励方差，高方差（时对时错）优先、低方差降权，同预算下比随机选 query 收敛更快。
- 局限：模型要么一直是推理模式、要么一直通用模式，无法动态切换——这直接催生 Qwen3 的模式融合。

### 2.2 Qwen3：极小数据量与双模式

- 四段：Cold SFT 长 CoT → Reasoning RL → **Thinking Mode Fusion** → General RL。
- **Reasoning RL 的极致效率**：**3,995 个**数学 / 代码 / 科学 query、**170 步** GRPO，AIME 2024 **+15**（thinking 模式 81.5）。结论是 RL 的关键不在数据量，而在 query 的"信息量"——处于"有时能、有时不能"边界上的最有效。
- **Mode Fusion**：`<think>` 内推理由 `/think` 激活，`/no_think` 输出空标签直接作答；同一 query 生成两种模式混合 SFT，General RL 再巩固。
- **涌现行为**：thinking 模式下自动"预算自适应"（简单题短、难题长），无需显式长度控制。
- **Strong-to-weak 蒸馏**：Qwen3-235B → Qwen3-4B 蒸馏 + 少量 RL，从头 RL ~45 分 / 10× GPU，蒸馏路线 ~55 分 / 1× GPU，约 **1/10 成本**。

### 2.3 Qwen3.5：混合架构

- 60 层，每 4 层一组：3×GatedDeltaNet → MoE + 1×GatedAttention → MoE；512 专家 / 10 激活；262K 上下文；201 种语言；统一视觉-语言（原生而非插件）。
- GDN 是线性注意力变体（O(n) 而非 O(n²)），3:1 混比意味着 **75% 的层是线性复杂度**，长上下文推理成本大幅下降。
- 后训练影响：GDN 层梯度传播与标准 Transformer 不同，可能需要不同的 LR / clip 范围，但官方博客未披露具体变化。

## 三、关键工程点

1. **GSPO 修的是 MoE 的 token 级噪声**：一次更新就可能改变约 **10% 的专家路由**，token 级 ratio 在 1000+ token 序列上乘积式累积；GSPO 改为序列级几何平均，clip 范围从 O(1) 收到 O(10⁻³)，不再需要 Routing Replay（推导见 [2.5](../ch2/2.5-cispo-gspo.md)）。
2. **SAPO 修的是硬裁剪的梯度断点**：用 sigmoid 门控平滑衰减，τ_pos=1.0、τ_neg=1.05（负梯度影响全词表分布，需更保守）；温和假设下退化为序列级方法，但保留 token 级适应性，已在 **Qwen3-VL** 系列生产验证（见 [2.6](../ch2/2.6-sapo.md)）。
3. **算法迭代靠工程反馈**：GSPO 解决 MoE 路由不稳、SAPO 解决大规模 collapse，两者都先在 Qwen 生产模型（含 Qwen3-VL）上验证再公开。

## 四、失败经验

- **Qwen2.5 的模式僵化**：没有 thinking / non-thinking 切换，直接导致 Qwen3 增加 Mode Fusion 阶段。
- **硬裁剪在后期振荡**：ratio 越过阈值梯度突变为零，策略接近最优时最易抖；这是 SAPO 的直接动机。
- **大规模 collapse**：GSPO 与 GRPO-R2 在 Qwen 内部大规模训练中出现过"先升后急降"的训练曲线。
- **Qwen3.5 披露不足**：只有官方博客、无 arXiv 技术报告，后训练细节基本空白，不要外推。

## 五、2026 变化

- 从"改算法"转向"**扩环境**"：Qwen3.5 官方承认没有新 RL 算法，增益来自 RL 任务与环境规模化；Qwen3.8-Max 把环境拆成 Task / Workspace / Harness 三轴（[4.2](../ch4/4.2-environment.md)）。
- **系统层**：QwenGyre（[2609.33848](https://arxiv.org/abs/2609.33848)，长程异步 RL，**1.78×** 加速）与 TRACE（[2610.07767](https://arxiv.org/abs/2610.07767)，FP4 RL 训推对齐，rollout 最高 **5.4×**），一致性见 [4.3](../ch4/4.3-infra-consistency.md)。
- 旗舰参数反降：Qwen3.8-Max 2.4T/95B → Qwen4-Max 2.4T/**71B**，后训练细节未披露。
