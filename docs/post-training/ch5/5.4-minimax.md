# 5.4 MiniMax

!!! abstract "本节摘要"
    MiniMax 是"问题驱动"的样本：01 用 Lightning Attention 支撑百万级上下文后训练，M1 诊断出 GRPO 会裁掉稀有反思 token 并提出 CISPO（**2×** 训练速度，$534K 训出 AIME 86.5），M2.5 的 Forge 框架以 Prefix Tree Merging 换来 **40×** 多轮训练加速。三步都是"先在生产里撞墙、再改算法或框架"的闭环。

---

## 一、发布矩阵

| 模型 | 日期 | 规模 | 后训练要点 |
|---|---|---|---|
| **MiniMax-01** | 2025-01 | 456B / 45.9B | 五阶段（短 SFT → 长 SFT → 短 DPO → 长 DPO → RL）；长短分离；原生 1M 上下文 |
| **MiniMax-M1** | 2025-06 | 同 01 基座 | CPT 7.5T → 长 CoT SFT → CISPO RL（512 H800 × 3 周）；AIME 86.5 |
| M2 | 2025-10 | 230B / 10B | 激活参数减 78%，定位编码 / Agent；延续 CISPO，无公开论文 |
| **M2.5** | 2026-02-12 | 229.9B / 9.8B | **Forge + CISPO**：10 万+ 真实 scaffold；process + 完成时间 + outcome 复合奖励 |
| M2.7 | 2026-03-18 | 229B 级 | **自我进化**：模型参与自身 RL harness 与训练迭代，吸收 30–50% 日常工作量 |
| M3 | 2026-06-01 | 未公开 | 官方未披露 RL；技术角色由 MSA 论文承担；**不要假设沿用 Forge / CISPO** |

## 二、后训练 Pipeline

### 2.1 01：五阶段与长短分离

- 短 SFT → 长 SFT（64K–1M）→ 短 DPO（~150K 对）→ 长 DPO → online RL（GRPO 变体）；四维 RM：Correctness / Truthfulness / Helpfulness / Harmlessness。
- **长短分离**是核心设计：混训会让短数据主导梯度、长上下文能力退化，且"简洁"与"完整"的偏好直接冲突。
- 架构：456B/45.9B MoE、原生 1M（外推 4M）、Lightning Attention 7:1 线性:Softmax、Global Router。

### 2.2 M1：CISPO

- **诊断**：GRPO 的 token 级裁剪会掐掉 "Wait / Actually / Let me reconsider" 这类**稀有但关键的反思 token**——旧策略下概率低、训练后概率涨，ratio 极大，正好被 clip 截断，推理能力的核心行为反而被抑制。
- **做法**：改裁**序列级 ratio**（先累乘再开 T 次方、整体 clip），稀有 token 的大 ratio 被序列平均稀释；额外收益是 **2× 训练速度**（不必为梯度保存每 token ratio）。与 GSPO 几乎同期独立提出（推导见 [2.5](../ch2/2.5-cispo-gspo.md)）。
- **成本**：512 H800 × 3 周 ≈ **$534K**，约为 DeepSeek-V3 总训练成本（$5.576M）的 1/10。

### 2.3 M2.5：Forge 框架

| 组件 | 问题 | 方案 |
|---|---|---|
| Windowed FIFO | 轨迹长度从几步到数百步，等最慢的会让 GPU 空转 | 固定窗口 W=0.3N，FIFO 替换最老轨迹并支持状态恢复 |
| Prefix Tree Merging | 多轮对话的共享前缀反复计算 | 合并成 Trie 结构，**40×** 多轮训练加速 |
| 复合奖励 | Agent 任务没有 0/1 判定 | process reward + 任务完成时间 + reward-to-go |

规模：100K+ 真实世界 Agent 环境（浏览器 / API / 代码执行）。M2.5 在 Agent 基准上与 Claude Opus 4.6 相当，推理成本约 **1/10**。

## 三、关键工程点

1. **优化器超参是 RL 的第一道坎**：VeRL 默认 Adam（β₂=0.999、ε=1e-8）在 M1 上完全训不动，改成 **β₂=0.95、ε=1e-15** 才收敛——奖励信号比预训练 loss 稀疏得多、波动更大。
2. **输出头必须 FP32**：BF16 的 logit 头在极小概率 token 上分不清 log(1e-7) 与 log(1e-8)，策略梯度方向会错。
3. **序列级裁剪的收益是双份**：既修掉稀有 token 被裁的问题，又省掉 per-token ratio 的显存与计算。

## 四、失败经验

- **长-短冲突**：混合长短数据做 SFT/DPO，短数据主导梯度、长上下文退化；必须分阶段训练。
- **GRPO 裁掉反思 token**：这与 R1-Zero 里反思词频只增 5–7 倍的现象互为证据——clip 会压制这类行为的涌现。
- **M3 的披露真空**：官方没有一句"沿用 Forge / CISPO"，算法继承不应默认成立。

## 五、2026 变化

- 主角从模型转向**框架**：Forge 的三模块解耦（Agent 侧 / 中间件 / 训练推理侧）+ Windowed FIFO（W=0.3N）+ prefix-tree merging 40× + 非对称 IS clip，成为可复用的 Agent-Native RL 基础设施（[4.2](../ch4/4.2-environment.md)）。
- 训练进入"**自我进化**"阶段：M2.7 让模型承担自身 RL 研究流程的 30–50%、80% 新增代码由模型生成，但技术细节极少。
- M2 系列的完整后训练细节在论文 [2605.26494](https://arxiv.org/abs/2605.26494)，不在发布博客里。
