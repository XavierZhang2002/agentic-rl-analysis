# 2.11 LongCat（美团）

!!! abstract "本节摘要"
    LongCat 是 2026 年唯一把"环境一致性"当成一等问题的厂商。三代模型（Flash-Thinking-2601 / 2.0 / 2.5）的共同特点是：**全流程国产算力 + 全流式异步 + 大规模长程 RL**。它公开的失败经验——环境数据库不一致会产生有偏负奖励——比大多数方法论更有价值。

## 二、后训练框架

### 2.1 Flash-Thinking-2601：领域并行专家 + DORA

- **领域并行专家训练 + 融合**：按领域训专家，再合并，而不是一个大混合 RL。
- **DORA 全流式异步**：
  - request load ratio **63%**——主动放弃约 37% 吞吐换 staleness 可控；
  - 比同步实现快 **2–4×**；
  - 官方明确承认这是"为控 staleness 付出的效率代价"。
- **GSPO** 作为基础算法，加**抗噪 RL**（环境噪声显式建模）。
- **Heavy Thinking**：按难度分配思考预算。

### 2.2 LongCat-2.0：多教师在线蒸馏 + MOPD

- 按能力类型分三类专家：**Agent / Reasoning / Interaction**；
- 用**多教师在线蒸馏**合并，再叠加 **MOPD**；
- 1M 上下文的中训练，累计数万亿 token。

### 2.3 LongCat-2.5：长程 RL + W4A4

- **大规模长程 RL**：把真实 agent 的失败轨迹转成可复现、可验证的训练任务；
- **W4A4 量化**：专家权重与激活同时 4bit，配合国产加速器；
- **训推数值一致性**是官方强调的重点（见 [2.5](./themes/05-infra-consistency.md)）。

## 三、最有价值的一条经验：环境数据库一致性

!!! danger "这个坑不会报错，只会静默污染奖励"
    **现象**：某些"本应成功"的轨迹被标为失败，模型因此学到"这样做不对"。

    **根因**：盲目给环境注入随机工具节点，会触发**未满足依赖的级联失败**、破坏跨工具的数据库一致性。结果就是——**正确解执行失败，被判为失败，引入有偏的负奖励**。

    **对策**：沿原可执行工具链做 **BFS 受控扩张**；每次扩张后跑"已知正确解"回归测试。

这是 agentic RL 数据侧最隐蔽的污染源：不报错、不降指标，只是让模型慢性变差。详见 [2.4 数据与环境](./themes/04-data-and-environment.md)。

## 四、国产算力工程

- 中训练最长 **1M token** 序列，累计训练量数万亿 token；
- 围绕**超节点**优化任务分工，让参数与数据的主要通信走超节点内高速互联；
- 长上下文 SFT 的单卡训练吞吐较 DDP 基线提升 **86%**（相当于 1 张卡干 1.86 张卡的活）；
- 推理用 **W4A4**，专家权重与激活同时 4bit。

## 五、怎么读 LongCat 的报告

- **值得读**：DORA 的异步设计（为什么是 63% 而不是 90%）、环境扩张的 BFS 策略。
- **别期待**：算法层的创新——它基本沿用 GSPO / OPD / MOPD 这套既有组合。
- **注意**：2.0 没有 arXiv 技术报告（只有博客 + 模型卡），2.5 权重未开源。
