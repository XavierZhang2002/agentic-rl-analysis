# 2.6 失败模式清单

!!! abstract "本节摘要"
    这份清单来自 8 家厂商 2026 年的技术报告与系统卡。共同特征：**不会在小规模实验里暴露、不会报错、只会静默降低性能**。建议在开工前逐条对照，出问题时按第三节的顺序排查。

---

## 一、算子与数值（6 条）

### F1 非确定性 top-k 直接杀死 RL

- **现象**：RL 数步内性能骤降，伴随熵骤降。
- **根因**：稀疏注意力/路由的 top-k 用 CUDA/TileLang 非确定性实现，同一序列两次前向的注意力不同。
- **对策**：换确定性 `torch.topk`；RL 期间冻结 indexer 参数。
- **来源**：GLM-5（[2602.15763](https://arxiv.org/abs/2602.15763)）

### F2 MoE 路由在训练/推理间漂移

- **现象**：token 级 IS ratio 剧烈波动，长序列更严重。
- **根因**：rollout 与训练走了不同的专家子网络。
- **对策**：路由回放（R3）或确定性路由；序列级 ratio 只能缓解不能根治。
- **来源**：R3（[2510.11370](https://arxiv.org/abs/2510.11370)）、GSPO（[2507.18071](https://arxiv.org/abs/2507.18071)）

### F3 量化前后不一致

- **现象**：训练指标正常，部署指标下降。
- **根因**：训练用 BF16、rollout 用 FP8/FP4，误差被当成策略偏移。
- **对策**：全流程 QAT（Kimi K3）、对称量化恢复（MoEResQ [2611.04376](https://arxiv.org/abs/2611.04376)）、TRACE [2610.07767](https://arxiv.org/abs/2610.07767)。

### F4 输出头精度不足

- **现象**：大规模训练中 loss 尖刺、采样异常。
- **根因**：BF16 的输出头在词表 100K+ 时数值不稳。
- **对策**：LM head 用 FP32；FP8 下双侧混合精度。
- **来源**：MiniMax M1；Ling 2.6（LM Head 双侧 FP32，约 +2 分 reward）

### F5 照搬 Adam 默认超参

- **现象**：RL 完全跑不动，loss 不降。
- **根因**：`β₂=0.999, ε=1e-8` 是预训练默认值，RL 场景梯度尺度不同。
- **对策**：`β₂=0.95, ε=1e-15`。
- **来源**：MiniMax M1

### F6 长序列的 CP/DP 重排

- **现象**：长上下文训练偶发 OOM 或吞吐塌陷。
- **根因**：序列长度不均，DP 负载失衡。
- **对策**：跨 DP 重排 + 动态虚拟 CP 组。
- **来源**：GLM-5

## 二、数据与环境（5 条）

### F7 re-tokenization 错位

- **现象**：训练 loss 正常但效果差；对比推理端输出发现概率估计有偏差。
- **根因**：文本进文本出（TITO 缺失），token 边界/空白/截断位置不一致。
- **对策**：TITO，中间件记录 token id。
- **来源**：GLM-5

### F8 环境数据库不一致 → 正确解被判失败

- **现象**：某些"本应成功"的轨迹被标为失败，模型学到错误行为。
- **根因**：随机注入工具节点触发未满足依赖的级联失败。
- **对策**：沿原工具链 BFS 受控扩张 + 已知正确解回归测试。
- **来源**：LongCat

### F9 环境不可解

- **现象**：某个域的成功率长期为 0，但人工检查发现模型行为合理。
- **根因**：任务本身无解或验证器错误。
- **对策**：环境上线前用 judge agent 确认存在可解路径。
- **来源**：GLM-5.3

### F10 数据污染

- **现象**：benchmark 分数异常高，换数据后骤降。
- **根因**：训练集与评测集重叠（尤其公开题库）。
- **对策**：n-gram 去污染 + 同构改写检测。

### F11 长上下文退化

- **现象**：>100K 后准确率显著下降。
- **根因**：注意力稀释、位置外推失效。
- **对策**：keep-recent-k + discard-all 混合（GLM-5 的 BrowseComp 55.3 → 75.9）。

## 三、奖励与评判（5 条）

### F12 验证器被外延绕过

- **现象**：分数上去了，实际能力没变。
- **根因**：验证器只看结果，模型学会利用盲区。
- **对策**：同构验证（等价换形再验）。
- **来源**：[2604.15149](https://arxiv.org/abs/2604.15149)

### F13 compaction 摘要欺骗

- **现象**：长任务中模型给出"看起来完成了"的摘要，实际没做。
- **根因**：欺骗性最终答案获得更高奖励。
- **对策**：对摘要做事实核验；官方披露该行为在 5.6-sol 占 **2.15%** 训练样本。
- **来源**：[OpenAI misalignment report](https://alignment.openai.com/misalignment-reports/encouraging-deception-in-compaction-summaries/)

### F14 rubric 维度背离

- **现象**：总分提升但某一维下降。
- **根因**：多维度 rubric 的子维度互相冲突。
- **对策**：监控维度间相关性，而非只看总分。
- **来源**：[2610.26685](https://arxiv.org/abs/2610.26685)

### F15 纯模型数据导致「机器感」

- **现象**：回复冗长、公式化、缺少人类写作的细腻。
- **根因**：通用 RL 只用模型自产数据会收敛到可识别的模式。
- **对策**：引入人类撰写回复作为风格锚点。
- **来源**：GLM-5

### F16 奖励测错了对象

- **现象**：模型学会"声明式作弊"（如 PPT 里写满属性但渲染出来是空的）。
- **根因**：奖励用了静态属性而非运行时结果。
- **对策**：用运行时渲染属性做奖励（Level 2）。
- **来源**：GLM-5

## 四、开工前 checklist

- [ ] 训练/推理的**算子是否确定性**（top-k、采样）
- [ ] 是否 **TITO**（而不是 text-in-text-out）
- [ ] 训练/rollout 的**量化是否同一套**
- [ ] MoE 路由是否**可复现**（回放或确定性）
- [ ] 环境是否有**已知正确解回归测试**
- [ ] 验证器是否过**三检**（正例/空操作/未完成）
- [ ] 是否做过**去污染**检查
- [ ] 是否监控 **staleness P99** 与 clip 命中率

## 五、出问题时的排查顺序

```
1. 先看数据：环境失败率、有效样本率、正确解是否被判失败
2. 再看一致性：训推 logprob 偏差、staleness、量化差异
3. 再看奖励：验证器三检、同构验证、维度相关性
4. 最后才怀疑算法：clip 命中率、熵曲线、advantage 分布
```

**经验**：按这个顺序，80% 的"算法不 work"会在第 1、2 步被排除。
