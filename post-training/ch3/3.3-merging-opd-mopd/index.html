    3.3 合并机制：OPD / MOPD¶

    本节摘要

    2026 年最集体的一次范式转移：不再让一个模型在混合 RL 里同时学所有东西，而是先训多个领域专家，再用在策略蒸馏（on-policy distillation, OPD）把它们合并回一个模型。DeepSeek（>10 → >40 教师）、Kimi K3（9 专家 + MOPD）、GLM-5（跨阶段蒸馏）、LongCat 2.0（多教师 + MOPD）、Qwen3.5-Omni（跨模态 OPD）都在做同一件事。

    与 1.12 的关系

    1.12 的演进图是"单模型内换目标函数"的历史。本节要补的是演进图之外的一条新支线——模型之间的合并。它不是替代前面的算法，而是在算法之上多了一层"如何把多个专家变成一个"。

    一、为什么要合并¶

    1.1 混合 RL 的三个瓶颈¶

    把数学、代码、agent、对话、安全放进同一次 RL 训练，会遇到：

    1. 奖励尺度冲突：数学的 0/1 与 agent 的稀疏过程奖励不可比；
    2. 能力遗忘：后续阶段优化会降级前序阶段已建立的能力（3.2 节挑战五）；
    3. 数据配比敏感：某个域的数据稍多，就会挤占其他域的梯度。

    1.2 专家路线的逻辑¶

    与其在一个模型里平衡五个目标，不如：

    域 1 ──► SFT + RL ──► 专家 1 ─┐
域 2 ──► SFT + RL ──► 专家 2 ─┼──► 合并（OPD/MOPD）──► 最终模型
域 3 ──► SFT + RL ──► 专家 3 ─┘

    每个专家只需要对自己的域负责，训练目标单一、超参独立；合并阶段再解决"怎么把能力装回一个模型"。

    二、四种实现¶

    2.1 GLM-5：跨阶段在线蒸馏（教师 = 各阶段 checkpoint）¶

    GLM-5 的第五阶段不是新的 RL，而是把前四个阶段（SFT / Reasoning RL / Agentic RL / General RL）的最终 checkpoint 当教师，做一个在线蒸馏：

    • 训练 prompt 从各教师对应的 RL 训练集按比例混合采样；
    • 教师 logits 由推理引擎产出（不占用训练侧显存）；
    • batch 1024、group size = 1（不再需要多样本估 advantage）；
    • advantage 直接由"与教师的差距"计算。

    目的：缓解顺序优化导致的累积能力退化——相当于一个"统一的能力恢复阶段"。

    2.2 DeepSeek V4 / V4.1：多教师全词表 OPD¶

    • 每个领域先独立 SFT + GRPO 训专家；
    • 再用 >10 个教师（V4.1-Flash 扩到 >40 个）做 reverse-KL 的 on-policy 蒸馏合并；
    • 关键词是 全词表：不是只对齐 top-k token，而是在整个词表上对齐分布。

    V4.1-Flash 的技术报告里有一句很重要的话："不引入新后训练算法，增益几乎全部来自数据/环境合成与合并"。

    2.3 Kimi K3：MOPD（per-token OPD reward）¶

    • 3 个域 × 3 个 effort 档 = 9 个 RL 专家；
    • 合并用 MOPD：把 OPD 的奖励做成 per-token 形式，并 clip 到 \(\pm R_{\max}\)；
    • 报告里有一个反直觉结论：更细的 top-k 蒸馏没有收益——全词表/分布级对齐已经足够。

    2.4 LongCat 2.0 与 Qwen3.5-Omni：两类变体¶

    • LongCat 2.0：Agent / Reasoning / Interaction 三类专家 + MOPD 融合，是"按能力类型分专家"的代表。
    • Qwen3.5-Omni：跨模态 OPD——把文本能力蒸馏给音频侧（Thinker 阶段）。这说明 OPD 不只是"合并专家"，也是能力迁移的工具。

    三、为什么是 OPD，不是普通蒸馏或混合 RL¶

    方案 数据来源 分布偏移 代价
    SFT 蒸馏（用教师输出做数据） 教师生成 学生学到的是"教师采样的轨迹"，exposure bias 明显 低
    混合 RL（一个模型多目标） 学生自己采样 无 目标冲突、配比难调
    OPD（在策略蒸馏） 学生自己采样，教师逐 token 打分 无（on-policy） 需要教师在线推理

    OPD 的关键优势：学生走自己的轨迹，教师只在每个 token 上给"应该是什么分布"。这样既避免了 SFT 蒸馏的 exposure bias，又避免了混合 RL 的多目标冲突。

    📖 一个容易混淆的点

    DeepSeek 的 OPD 是 reverse KL（学生去覆盖教师的分布），Kimi 的 MOPD 是 per-token 奖励 + clip。两者都叫"on-policy distillation"，但奖励形式不同——写报告或复现时不能混用。

    四、工程代价：教师越多，调度越难¶

    GLM-5.3 的 slime 多教师 OPD 给出了目前最完整的工程方案：

    1. 动态教师切换：GPU 上只加载当前激活的教师；
    2. 预取：其余教师放本地存储（不占主机内存），下一个教师在后台预加载；
    3. 联合调度：router 与 slime 协同做负载均衡，容量一释放就路由新请求。

    即使如此，教师数量仍然受限于：显存（同时加载几个）、带宽（权重换入换出）、调度复杂度（几十个教师的优先级与配比）。

    五、风险：教师会把坏习惯一起蒸进来¶

    • 教师本身是 RL 出来的，它的 reward hacking、格式怪癖、过度冗长都会进入学生；
    • 教师选择偏差：如果某个域的教师恰好在该域"过拟合"，学生会继承这个偏差；
    • 蒸馏目标与 RL 目标的冲突：合并阶段通常不再做 RL，等于放弃了合并后的继续优化。

    一个可检验的判据

    如果合并后的模型在训练分布内提升、但在分布外下降，说明它在复制教师而不是泛化。此时应该回到"增加环境多样性"，而不是"再加教师"。
