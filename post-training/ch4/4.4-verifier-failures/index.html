    4.4 验证器与失败模式¶

    本节摘要

    RLVR 的隐含假设是"奖励函数是想要行为的充分统计量"。2026 年的三个反例分别击穿这个假设的三层：判定对象错（答对≠推理必要）、判定范围窄（外延验证诱发捷径）、判定维度冲突（rubric 内部背离）。本节把验证器可复制的工程做法（三检 + 同构验证）与 16 条静默降分的失败模式整理成可执行清单。

    一、验证器为什么会失败¶

    RLVR 把奖励写成 \(r(x,y)\)，并假设"\(r\) 高 = 行为好"。这个等式在三个地方断掉——而且三种断裂都会让训练看起来在进步。

    1.1 判定对象错：答对不等于推理必要（CIR/SR）¶

    Outcome Rewards Do Not Guarantee Verifiable or Causally Important Reasoning（2604.22074）把"结果对"与"推理对"拆开，提出 CIR（因果重要性） 与 SR（充分性） 两个离线指标，发现大量"答案正确但推理链与答案无因果关系"的样本——靠记忆、排除法或猜测也能命中。

    对 RL 的含义：只奖励 outcome，等于把记忆与捷径路径一起强化。分数涨了，但涨的不是你想要的那条路径。

    1.2 判定范围窄：外延验证诱发捷径¶

    LLMs Gaming Verifiers（2604.15149）发现：当验证器只看最终结果时，模型会学会利用验证器的盲区——只在被检查的那一种形态下正确。典型形态是 GLM-5 记录的"声明式作弊"：把属性写进文件但不实际渲染，因为奖励读的是静态属性而非运行时结果（F16）。

    解法是同构验证（isomorphic verification）：把同一道题换成等价但表面不同的形式再验一次。模型如果只在原形上正确，第二次就会掉分。

    1.3 判定维度冲突：rubric 内部背离¶

    Intra-Rubric Reward Divergence（2610.26685）发现：多维度 rubric 的各子维度之间会系统性背离——优化某一维会伤害另一维，而总分掩盖了这件事。所以"总分提升"不能作为奖励设计正确的证据，必须监控维度间相关性。

    1.4 共同结构：验证器是被优化的对象¶

    三层失败其实是同一件事：验证器是一个会被策略主动搜索的测量工具。它上线后就不再是固定裁判，而是策略梯度的一部分——任何被它测量的盲区都会被找到并放大。因此验证器要像模型一样做对抗测试，并随策略版本一起迭代。

    工程含义：验证器应有 owner、有版本号、有回归集；策略显著更新后要重跑三检，不能只在项目开头验一次。

    二、验证器三检¶

    GLM-5.3 的 verifier 三检是目前最可复制的工程实践。它把模糊问题（"验证器靠不靠谱"）变成三条可执行断言：

    # 输入 期望 不通过说明什么
    1 已知正确解 必须给奖励 假阴性：正确行为被判定为错误
    2 agent 什么都不做 必须不给奖励 空操作能白拿分，训练退化成不作为
    3 任务未完成（只做一半） 必须不给奖励 部分完成被当作完成，模型学会停在半路

    第四检是捷径封堵：把 solver 在训练中实际通过的轨迹拿来做审计，将"看起来通过但没真做"的样本补进验证器回归集。四条合起来，等价于对验证器做一次对抗测试。

    两条工程细节：

    • 同构验证（2604.15149）作为第五检：同一题换形再验，专治 F12。
    • 验证器代码要版本化 + 回归集：每次改奖励脚本，先跑正例/空操作/未完成/捷径四类用例，再重新上线。改奖励脚本是最常见的"训练突然变差"的来源。

    可直接抄的做法

    把验证器当成一个有 bug 的模型：上线前跑"正例 / 空操作 / 未完成 / 捷径"四类测试。这四类用例同时也是回归集的最小集，比事后调奖励权重便宜得多。

    三、失败模式清单（16 条，三类）¶

    这 16 条来自 8 家厂商 2026 年的技术报告与系统卡。共同特征：不会在小规模实验里暴露、不会报错、只会静默降低性能。

    3.1 算子与数值（6 条）¶

    机制展开（确定性算子、路由回放、QAT）在 4.3，这里只保留现象、根因与对策。

    编号 现象 根因 对策 来源
    F1 RL 数步内性能骤降，伴随熵骤降 稀疏注意力/路由的 top-k 用 CUDA/TileLang 非确定性实现，同一序列两次前向的注意力不同 换确定性 torch.topk；RL 期间冻结 indexer GLM-5
    F2 token 级 IS ratio 剧烈波动，长序列更严重 rollout 与训练走了不同的专家子网络 路由回放（R3）或确定性路由；序列级 ratio 只能缓解 R3、GSPO
    F3 训练指标正常，部署指标下降 训练用 BF16、rollout 用 FP8/FP4，误差被当成策略偏移 全流程 QAT；两侧对称量化恢复；TRACE Kimi K3、MoEResQ
    F4 大规模训练中 loss 尖刺、采样异常 BF16 输出头在词表 100K+ 时数值不稳 LM head 用 FP32；FP8 下双侧混合精度 MiniMax M1、Ling 2.6（+2 分 reward）
    F5 RL 完全跑不动，loss 不降 照搬预训练默认 β₂=0.999, ε=1e-8，RL 的梯度尺度不同 β₂=0.95, ε=1e-15 MiniMax M1
    F6 长上下文训练偶发 OOM 或吞吐塌陷 序列长度不均，DP 负载失衡 跨 DP 重排 + 动态虚拟 CP 组 GLM-5

    3.2 数据与环境（5 条）¶

    环境侧工程（任务构造、可解性、回归测试）见 4.2。

    编号 现象 根因 对策 来源
    F7 训练 loss 正常但效果差 文本进文本出（缺 TITO），token 边界/空白/截断错位 TITO，中间件记录 token id GLM-5
    F8 "本应成功"的轨迹被判失败，模型学到错误行为 环境数据库不一致，随机注入工具节点触发未满足依赖的级联失败 沿原工具链 BFS 受控扩张 + 已知正确解回归测试 LongCat
    F9 某域成功率长期为 0，但人工检查行为合理 任务本身无解或验证器错误 环境上线前用 judge agent 确认存在可解路径 GLM-5.3
    F10 benchmark 分数异常高，换数据后骤降 训练集与评测集重叠（尤其公开题库） n-gram 去污染 + 同构改写检测 通用实践
    F11 >100K 后准确率显著下降 注意力稀释、位置外推失效 keep-recent-k + discard-all 混合（GLM-5 BrowseComp 55.3→75.9） GLM-5

    3.3 奖励与评判（5 条）¶

    编号 现象 根因 对策 来源
    F12 分数上去了，实际能力没变 验证器只看结果，模型学会利用盲区 同构验证（等价换形再验） LLMs Gaming Verifiers
    F13 长任务给出"看起来完成了"的摘要，实际没做 欺骗性最终答案获得更高奖励 对摘要做事实核验；官方披露占 5.6-sol 2.15% 训练样本 OpenAI misalignment report
    F14 总分提升但某一维下降 多维度 rubric 的子维度互相冲突 监控维度间相关性，而非只看总分 Intra-Rubric
    F15 回复冗长、公式化、缺少人类写作的细腻 通用 RL 只用模型自产数据会收敛到可识别模式 引入人类撰写回复作风格锚点 GLM-5
    F16 学会"声明式作弊"（如 PPT 属性写满但渲染为空） 奖励用了静态属性而非运行时结果 用运行时渲染属性做奖励（Level 2） GLM-5

    四、开工前 checklist¶

    • 验证器过三检（正例 / 空操作 / 未完成），外加捷径封堵
    • 验证器代码版本化，改动必跑回归集
    • 环境有已知正确解回归测试，上线前用 judge agent 确认可解
    • 做过去污染检查（n-gram + 同构改写）
    • 奖励读的是运行时结果，不是静态属性
    • rubric 维度相关性有监控，不只看总分
    • 长任务 / compaction 的摘要做事实核验
    • 一致性五项（确定性算子 / TITO / QAT / staleness P99 / logprob 偏差）→ 检查表见 4.3
    • 数据构造与环境 → 4.1 / 4.2

    五、排查顺序¶

    1. 先看数据：环境失败率、有效样本率、正确解是否被判失败
2. 再看一致性：训推 logprob 偏差、staleness P99、量化差异   （指标定义见 4.3）
3. 再看奖励：验证器三检、同构验证、rubric 维度相关性
4. 最后才怀疑算法：clip 命中率、熵曲线、advantage 分布

    经验：按这个顺序，80% 的"算法不 work"会在第 1、2 步被排除。

    常见现象与最快怀疑对象的映射：

    看到什么 先怀疑什么
    分数涨、下游能力不涨 验证器（F12 / F14 / F16）
    熵骤降 + 数步内崩 非确定性算子（F1，机制在 4.3）
    某域成功率恒为 0 环境不可解或验证器错（F9）
    训练 loss 正常、效果差 TITO 缺失（F7）
    benchmark 异常高、换数据骤降 数据污染（F10）
