    2.7 信任域与目标函数的新解法¶

    本节摘要

    第 1.4–1.10 节的演进是一条线：如何把 ratio 裁剪得更平滑（对称 → 非对称 → 裁权重 → 序列级 → 软门控）。2026 年的研究把问题重新打开了——争论不再是"clip 长什么样"，而是约束哪个量（ratio 还是真实散度）、在哪一层约束（token / sequence / list）。本节介绍四条代表性路线，并给出一个可以替代"演进链"的二维矩阵。

    问题的重新表述¶

    1.10 节结尾给出的统一视角是：所有算法都可以写成

    \[ \mathcal{L} = f(r_t) \cdot \hat{A}_t, \qquad r_t = \frac{\pi_\theta(y_t \mid y_{<t})}{\pi_{\theta_{\text{old}}}(y_t \mid y_{<t})} \]

    区别只在 \(f(\cdot)\) 的形状（硬裁剪 / 非对称 / 软门控）。这个视角简洁，但隐含了两个假设：

    1. 被约束的量是 ratio \(r_t\)——即用重要性采样比率的偏离程度来代理"策略走了多远"；
    2. 约束作用在 token 上——每个 token 独立判断是否越界。

    2026 年的四项工作分别打在这两个假设上。

    路线一：DPPO —— 不用 ratio，直接估计散度¶

    论文：Rethinking the Trust Region in LLM Reinforcement Learning（arXiv:2602.04879，ICML 2026，PMLR 306:100675）

    核心主张：ratio \(r_t\) 只是"策略偏移"的带噪估计。在 LLM 的稀疏奖励 + 长序列场景下，单个 token 的 ratio 方差很大，用一个高方差的量去卡信任域，等于用噪声做门控。

    DPPO 的做法是把目标写成带散度约束的优化问题，直接估计散度：

    \[ \max_\theta \; \mathbb{E}\left[\hat{A}_t\right] \quad \text{s.t.} \quad \hat{D}_{\text{TV}}(\pi_\theta \,\|\, \pi_{\theta_{\text{old}}}) \le \delta \]

    其中 \(\hat{D}_{\text{TV}}\) 用样本估计（而不是把每个 token 的 ratio 硬塞进 clip 区间）。效果上，它保留了"不跑太远"的约束，但不再把"某个 token 的 ratio 恰好落在 \([1-\varepsilon, 1+\varepsilon]\) 外"当成策略发散的证据。

    路线二：TRM —— token 级 clip 管不住序列级散度¶

    论文：Trust Region Masking for Long-Horizon LLM Reinforcement Learning（arXiv:2512.23075，ICML 2026）

    核心主张：长序列下，经典分析给出的界是 \(O(T^2)\)——序列越长，token 级约束对序列级散度的控制越松。换句话说，即使每个 token 的 ratio 都在区间内，整条序列的分布也可能已经跑远。

    TRM 的解法是把约束提到序列层：

    \[ m(y) = \mathbb{1}\left[\max_{t} \big| \log \pi_\theta(y_t) - \log \pi_{\theta_{\text{old}}}(y_t) \big| \le \delta\right], \qquad \mathcal{L} = m(y)\cdot \hat{A}(y)\cdot \log \pi_\theta(y) \]

    用整序列的 mask 替代逐 token 的 clip，界从 \(O(T^2)\) 收紧到 \(O(T)\)。

    📖 一个直观的类比

    token 级 clip 像"每个路口限速 60"，序列级 mask 像"整段路平均速度限 60"。前者在长路上会积累出很大的总偏移——这正是长 CoT / 长 trajectory 上 GRPO 容易崩的原因之一。

    路线三：LPO —— 把 group-based PG 看成 simplex 上的投影¶

    论文：Listwise Policy Optimization: Group-based RLVR as Target-Projection on the LLM Response Simplex（arXiv:2605.06139，NeurIPS 2026）

    核心主张：GRPO 一族做的事，本质上是在"一个 prompt 的 G 条响应"构成的单纯形上做一次目标投影：

    \[ \pi_{\text{new}} = \arg\min_{\pi \in \Delta^{G-1}} \; \mathrm{KL}\!\left(\pi \,\Big\|\, \pi_{\text{ref}}\right) - \eta \cdot \mathbb{E}_{\pi}\left[\hat{A}\right] \]

    一旦这样表述，就能看清两件事：① 组内相对优势等价于"按 advantage 重新分配概率质量"；② token 级 clip 与这个几何解释并不一致——它约束的是逐 token 的局部量，而目标投影是 listwise 的。

    LPO 因此把优化改成 listwise 形式，并给了收敛性讨论。这是 2026 年唯一把 GRPO 家族从"启发式"提升到"有几何解释"的工作。

    路线四：OTB —— 不改约束，改方差¶

    论文：OTB: Optimal Token Baseline（arXiv:2602.07078）

    不是所有问题都要改信任域。OTB 的思路是：GRPO 的序列级 baseline 对 token 级优势的估计并不最优，用最优 token baseline 可以把方差压到更低，从而用 N=4 的采样达到 N=32 的效果，token 消耗降低约 65%。

    四者的定位差异

    • DPPO：换约束对象（ratio → 散度）
    • TRM：换约束层级（token → sequence）
    • LPO：换优化对象（逐 token → listwise 投影）
    • OTB：不改约束，改估计的方差

    二维矩阵：替代"演进链"的看法¶

    把 2025 的演进链放进一个二维空间，就会看到它只占了一个角落：

    token 级 序列级 listwise
    约束 ratio PPO / GRPO / DAPO / CISPO GSPO —
    约束散度 — TRM LPO
    不显式约束（靠方差控制） SAPO（软门控）/ OTB — —

    读法： - 2025 年的全部工作都在第一行"token 级 / 约束 ratio"这个格子里做精细化；GSPO 挪到了第二列，SAPO 把硬边界换成连续门控。 - 2026 年的 DPPO 挪到第二行（换成估计散度），TRM 挪到"序列级 + 散度"，LPO 挪到第三列（listwise）。 - 右下角的空格（listwise + 散度约束）目前还是空的——这是下一个可能的创新点。
