    1.4 奖励设计：从规则到 actor-as-GRM¶

    本节摘要

    当算法与数据都在收敛时，奖励是 2026 年最大的差异化变量。本节把头部厂商的奖励设计排成一条谱系：规则/可验证 → 判别式 ORM → 生成式 GRM → actor 兼任 GRM → rubric/checklist，给出各家的实际搭配、验证器设计的三条硬性检查，以及按任务选奖励的决策表；失效细节归到 4.4。

    奖励设计的分水岭出现在 2025–2026：在此之前，大多数团队的做法是"训一个 RM + PPO"；此后规则奖励先在小范围内取代 RM，再被生成式 GRM 与 rubric 扩到开放域，最后连"谁是评判者"都变了——DeepSeek V4 直接让 actor 兼任 GRM。本节按这条顺序排谱系、搭表、给检查项。

    一、五个层级¶

    层级 做法 代表 适用 主要风险
    L1 规则/可验证 答案匹配、单元测试、执行结果 数学、代码、SQL 有确定答案的任务 只覆盖可验证域
    L2 判别式 ORM 训练一个打分模型（Bradley-Terry 等） Qwen2.5 六维 RM、各家 reward model 通用对话、写作 reward hacking、长度偏差
    L3 生成式 GRM 让模型生成评判理由再打分 GLM-5 的 GRM、Kimi 的 Self-Critique Rubric 开放性任务、可解释性要求 方差大、推理成本高
    L4 actor 兼任 GRM 不单独训 RM，让 actor 自己当评判者 DeepSeek V4 大规模、域跨度广 评判与生成互相污染
    L5 rubric / checklist 多维度二值清单 CM2（2602.12268）、GLM-5.3 需要审计、可解释 维度间背离

    📖 一个容易看错的点

    L1 到 L5 不是替代关系，而是"覆盖范围"的扩展：L1 最可靠但最窄，L5 最宽但最难保证一致性。2026 年头部厂商的普遍做法是同时用 L1 打底 + L3/L5 提升上限。

    分层的轴是"谁来评判"；换一个轴——奖励的粒度——同一批方法会重新排布：L1/L2 只给整条轨迹一个分数，L5 的 rubric 能定位到"哪一维不达标"，而 process reward / Progress Advantage 把信号压到 step/token 级（见 3.1）。粒度越细，训练早期的信号越稠密，验证成本也越高。

    这条阶梯的每一级都在把"判断"从确定性推向生成式：L1 把判断写成程序，L2 把判断压成一个标量，L3 要求判断给出理由，L4 直接复用 actor 的生成能力，L5 把判断拆成清单。越往后能覆盖的开放域越大，但"判断标准由谁定义、能否复现"也越模糊——这正是后文三检要解决的问题。

    二、各家怎么搭¶

    五级谱系只是坐标，真正的选择体现在"用什么组合、谁当评判者、维度怎么组织"。把 2025 与 2026 两代技术报告并到一张表里，可以看到奖励来源的差异正在被"评判者的身份"取代：

    模型 奖励组合 维度 值得注意的点
    DeepSeek-R1 规则 RM + 偏好 RM 2 偏好 RM 限时使用（最后 400/1700 步），防 reward hacking
    DeepSeek-V3.2 规则 RM + 域特定 KL 多域 数学弱 KL、其他域强 KL，按域调节
    DeepSeek V4 规则 + actor-as-GRM（rubric 引导） 多域 放弃标量 RM/RLHF 路线；评判与生成联合优化
    Kimi K1.5 二元结果 + CoT RM（准确率 98.5%） 1 RM 自身也"思考"
    Kimi K2 / K2.5 RLVR + Self-Critique Rubric 3 类 rubric rubric 自评，闭环传递客观信号
    Qwen2.5 → Qwen3 六维独立 RM → 规则为主 6 → 规则 六维拆分降低单维 hacking；分维度构造 DPO 偏好对
    MiniMax-01 / M2 系列 4 维 RM / process + 完成时间 + outcome 复合 4 / 复合 长-短分离评估；把"效率"直接写进奖励
    GLM-5 / 5.3 规则 + 判别式 ORM + 生成式 GRM 三混合；5.3 环境内自动生成 verifier 多维 人类撰写回复作风格锚点；跨阶段 teacher 信号；verifier 上线前过三检
    Seed / VAPO MC return + 规则 RM 1 用于 Critic 预训练
    LongCat 规则/模型混合 + 抗噪 RL 多维 环境噪声（如 DB 不一致）会被当成负奖励，必须显式处理

    读表有两点：独立标量 RM 已退到边缘——R1 只在最后 400/1700 步用它，Qwen2.5 的六维 RM 是历史形态，2026 年的主流是"规则 + 生成式评判"；维度在变多、评判者在变少——维度从 1 拆到 6 甚至清单化，但越来越多的模型不再单独训评判模型。由此抽出三条搭配原则：

    • 规则打底：有确定答案的域优先 L1，把下限锁死；规则覆盖不到的部分才交给 L2–L5。
    • 拆分维度：标量总分最容易被单点 hack，拆成多维后局部作弊不直接变成全局奖励；代价是维度背离（见 4.4）。
    • 人类锚点：纯模型数据训出的 GRM 会奖励"机器感"，GLM-5 混入人类撰写回复作风格锚点。

    三、失效模式¶

    奖励给错比给少更贵：答案正确但推理链不必要（CIR/SR）、验证器被外延绕过、rubric 子维度相互背离，这三类失效都有 2026 年的论文证据，机制、出处与对策见 4.4 验证器与失败模式。

    四、验证器设计：三条硬性检查¶

    GLM-5.3 的工程实践是目前最可复制的（Baseten 解读）：

    1. 给定已知正确解 → 必须给奖励；
    2. agent 什么都不做 → 必须不给；
    3. 任务未完成 → 必须不给。

    三条检查抓的是不同的 bug：第一条抓假阴性（好轨迹被判坏），第二条抓空操作骗分，第三条抓半成品骗分。再加一条工程习惯：用 solver 的轨迹封堵捷径解——把模型找到的"作弊路径"显式写成反例。

    为什么这比调权重便宜

    调奖励权重是在未知空间里搜索；三检是在已知失败模式上做验证。前者要靠运气，后者可以写进 CI。

    五、奖励与流程的接口¶

    奖励选择不是全局常量，而是流程的函数（流程见 1.3）：

    • 串行四五段式：每段换奖励——Reasoning RL 用 L1，Agentic RL 用执行结果 + 过程分，General RL 用偏好/GRM；代价是要同时维护多套验证器/评判器。
    • 专家+合并：专家按域配奖励（数学 L1、对话 L3/L5），合并阶段不再跑 RL，奖励只用于筛数据与蒸馏。
    • 跨阶段蒸馏：前序 checkpoint 当教师，本质上是用"教师分布"替代奖励信号恢复能力（GLM-5 的做法），该阶段不依赖验证器判分。
