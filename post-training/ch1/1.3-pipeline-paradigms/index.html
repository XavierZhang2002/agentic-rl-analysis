    1.3 流程范式：三段式、四五段式、专家+合并¶

    本节摘要

    2026 年的后训练流程收敛成三种范式：三段式（SFT → RL → 对齐/蒸馏）、四五段式（加 AgenticRL 与 GeneralRL，末尾接跨阶段蒸馏）、专家+合并（多域专家各自 RL，再用 OPD/MOPD 合并）。本节给出各家的阶段表、选择依据，以及"阶段越多越容易遗忘"的三类处理方式。

    各家公开的技术报告里，算法与数据的差异在收窄，阶段的顺序与合并方式成了更能解释能力差异的变量：同样是 GRPO，GLM-5 串成五段、DeepSeek V4 拆成多个专家再合并（V4.1 的教师超过 40 个），最终能力画像完全不同。把 2026 年的流程排在一起，只有三种稳定范式，其余都是它们的变体。

    一、三种范式¶

    Base → SFT → RL（可验证域）→ 对齐/蒸馏 → 模型
    • 代表：DeepSeek V4.1-Flash（SFT → RL → OPD）、Seed1.5-Thinking
    • 适用：目标域集中、不需要同时覆盖推理与 agent
    • 优点：阶段少、回归风险低
    • 缺点：通用能力与安全对齐要靠最后一阶段"补"，容易顾此失彼
    Base → SFT → Reasoning RL → Agentic RL → General RL → 跨阶段蒸馏 → 模型
    • 代表：GLM-5（五段，最后一段是跨阶段在线蒸馏）
    • 适用：要同时做推理、agent、通用对话的全能模型
    • 优点：每段目标单一，超参独立
    • 缺点：能力遗忘——后段优化会降级前段能力；需要专门的恢复机制
    Base → 域1 SFT+RL → 专家1 ┐
     → 域2 SFT+RL → 专家2 ┼→ OPD / MOPD 合并 → 模型
     → 域3 SFT+RL → 专家3 ┘
    • 代表：DeepSeek V4（>10 教师，V4.1 >40）、Kimi K3（9 专家 + MOPD）、LongCat 2.0
    • 适用：域跨度大（数学 / 代码 / agent / 对话 / 安全）
    • 优点：绕开"多目标互相干扰"，每域可独立调参
    • 缺点：合并成本高（教师加载、调度、蒸馏质量），且合并后不再继续 RL

    二、各家实际的阶段表¶

    模型 阶段数 顺序 合并方式
    GLM-5 5 SFT → ReasoningRL → AgenticRL → GeneralRL → 跨阶段蒸馏 教师 = 前序各阶段 checkpoint
    GLM-5.2 / 5.3 同 5 段 同上 5.3 用多教师 OPD
    DeepSeek V4 3 专家 SFT+GRPO → 多教师 OPD >10 教师，reverse KL，全词表
    DeepSeek V4.1-Flash 3 SFT → RL → OPD >40 教师；明示不加新算法
    Kimi K3 2 + 9 专家 SFT → 9 个 RL 专家 → MOPD per-token OPD reward，clip ±R_max
    Kimi K2.5 3 SFT → zero-vision SFT → 文本-视觉联合 RL 无合并
    Qwen3.5-Omni Thinker 3 / Talker 4 专家蒸馏 → 跨模态 OPD → 交互对齐 RL 跨模态 OPD
    MiniMax M2 系列 多段 SWE-scaling 七段流水线 + 混合域 curriculum 混合域训练，非合并
    LongCat 2.0 多段 Agent / Reasoning / Interaction 专家 多教师在线蒸馏 + MOPD
    Ling 2.6 迁移 + RL 架构迁移预训练 → Evo-CoT / LPO / 双向偏好 无合并

    一个读表的技巧

    阶段数不等于复杂度。Kimi K3 只写了"2 段 + 9 专家"，但它的工程复杂度（QAT 贯穿、1M agentic RL、微虚机环境）远高于 GLM-5 的五段式。

    三、能力遗忘：三类处理方式¶

    阶段越多，后段越容易覆盖前段。2026 年有三种做法：

    做法 代表 机制 代价
    跨阶段蒸馏 GLM-5 用前序各阶段 checkpoint 当教师，做在线蒸馏恢复能力 额外一个训练阶段
    从 Base 重训 DeepSeek R1（Rejection Sampling SFT 阶段） 不从 RL checkpoint 继续，而是从 Base 重跑 浪费前序参数知识
    专家隔离 + 合并 DeepSeek V4 / Kimi K3 各域独立训，根本不共享参数 合并成本
    ## 四、工程细节：阶段之间怎么接
    1. 数据回灌：RL 阶段的拒绝采样结果回灌到下一轮 SFT（R1 的 RS SFT）。回灌比例过高会让模型"只会做见过的题"。
    2. checkpoint 选择：不要用最后一轮，用评测峰值的 checkpoint 当教师或起点。
    3. 评测口径统一：不同阶段用同一套 benchmark，否则无法判断是能力提升还是评测漂移。
    4. 配比：混合域训练时，域的采样比例要随训练进度调整（Qwen3.8-Max 的"在线数据均衡器"就是这个）。

    阶段之间能不能接得上，很大程度取决于异步与训推一致性（TITO、确定性 top-k、QAT），这部分见 4.3 基础设施与一致性。
